# WHITE-LABEL / COMPANY CUSTOMIZATION FEASIBILITY REPORT — RSHOTS BILLING

## 1. Executive Conclusion
The RShotsBilling POS is **PARTIALLY** ready for white-labeling. 

While the core data architecture already supports multi-tenancy (via `companyId` and scoped collections), the UI and document generation layers still rely heavily on hardcoded "RShots" branding or static configurations in `BusinessConfig`. 

**Feasibility Verdict**: **YES**, a single white-label application is achievable with minimal changes to the core engine, provided the UI and Document layers are refactored to consume the `UserSession` branding state exclusively.

## 6. Company Context Flow
The chain is fully implemented and operational:
1. **Auth**: `LoginViewModel` signs in user.
2. **Profile**: Fetches `StaffMember` -> gets `businessId`.
3. **Branding**: `App.kt` fetches `Company` doc by `businessId` -> calls `UserSession.updateFromCompany(company)`.
4. **Context**: `UserSession` stores all branding data as reactive `mutableStateOf`.

## 7. Multi-Company Feasibility
The current architecture **conceptually supports** infinite companies. 
- `Company A` and `Company B` have separate documents in `/companies`.
- Logging in as `Admin A` triggers `UserSession.updateFromCompany(A)`.
- The POS immediately changes its internal state to `A`.

## 8. Resale Architecture Compatibility
The proposed Vendor system (Resale) is **Fully Compatible**.
The Vendor layer sits above the Company layer. A Vendor can create `Company C`, and the white-label POS will simply load `Company C`'s configuration upon login, exactly like it does for `A` and `B`.

## 9. Protected Core (Do Not Modify)
- `FirestoreManager.kt` (Path resolution logic is correct).
- `SalesRepository.kt` / `InventoryRepository.kt` (Business logic is branding-agnostic).
- `AuthService.kt` (Identity logic).

## 10. Recommended Implementation Strategy
1. **Refactor `AppTheme.kt`**: Change `LightColors` to use `UserSession.primaryColor` and `secondaryColor` dynamically.
2. **Clean Generators**: Replace remaining hardcoded strings in `PdfReceiptGenerator` and `ExcelReportExporter` with `UserSession` properties.
3. **Logo Handler**: Implement a proper image loader for the `companyLogo` URL stored in `UserSession`.
4. **String Cleanup**: Move "RShots" strings in `BusinessConfig` to fallback-only constants.
